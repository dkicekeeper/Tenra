# Insights Product Audit — что показываем, что убрать, что добавить, уведомления

**Дата:** 2026-07-13
**Метод:** инвентаризация кода (`Services/Insights/**`, `Views/Insights/**`, [INSIGHTS_METRICS_REFERENCE.md](INSIGHTS_METRICS_REFERENCE.md)) + бенчмарк-исследование Copilot Money, Monarch, YNAB, Emma, Cleo, Rocket Money, Revolut, Kaspi/Halyk, Apple Wallet + отраслевые данные по push-нотификациям (Personetics, MX, Pushwoosh, Latinia).
**Статус:** реализовано 2026-07-13 (фазы A–D, см. «Статус реализации» внизу).

## 1. Что показывается сейчас

Экран «Аналитика» (`InsightsView`):
1. **Сводная шапка** — текущий бакет: доступный баланс, чистый поток, расходы, доходы + тренд к прошлому бакету → `InsightsSummaryDetailView`.
2. **Health Score** (0–100, 5 компонент) → `FinancialHealthDetailView` с рекомендациями.
3. **Фильтр-карусель** по 8 категориям.
4. **8 секций** (Расходы, Доходы, Бюджет, Регулярные, Денежный поток, Капитал, Сбережения, Прогнозы) — 26 активных метрик, сортировка по severity **внутри** секции.
5. Гранулярность: неделя/месяц/квартал/год/всё время (toolbar-меню).

Аудит 2026-04 уже удалил 3 дубля (`incomeSeasonality`, `spendingVelocity`, `savingsMomentum`).

## 2. Оценка текущих метрик

Критерии: **действенность** (подсказывает ли действие), **уникальность** (не видно ли это и так на других экранах), **недублируемость**.

### Ядро — оставить как есть (16)

| Метрика | Обоснование (бенчмарк) |
|---|---|
| `topSpendingCategory` | Table stakes во всех 8 приложениях |
| `monthOverMonthChange` | Основа weekly/monthly digest (Copilot, Apple) |
| `spendingSpike` | Аномалия против собственного среднего — дифференциатор (Copilot, Emma); кандидат №1 на push |
| `categoryTrend` | «Ползущая» категория 3+ мес — действенно (пересмотреть привычку) |
| `incomeGrowth`, `incomeSourceBreakdown` | Стандарт; breakdown ценен для фрилансеров |
| `budgetOverspend`, `projectedOverspend`, `budgetHeadroom` | Budget pacing = table stakes (Copilot pace line, Revolut daily allowance); первые два — push-кандидаты |
| `totalRecurringCost`, `subscriptionGrowth`, `duplicateSubscriptions` | Recurring-инвентарь = стандарт; duplicate — фича Rocket Money |
| `netCashFlow`, `savingsRate`, `emergencyFund` | Ядро финздоровья, входят в Health Score |
| `spendingForecast`, `projectedBalance` | Прогнозы — направление, куда идут Monarch/Copilot; база для push «прогноз низкого баланса» |

### Слабые — удалить или объединить (5)

| Метрика | Проблема | Решение |
|---|---|---|
| `incomeVsExpenseRatio` | Формула `income/(income+expenses)` неинтуитивна; полностью дублирует связку `savingsRate` + `netCashFlow`. Ни один бенчмарк не показывает такую метрику карточкой | **Удалить.** График «доходы vs расходы» остаётся в детали netCashFlow |
| `bestMonth` + `worstMonth` | Ретроспективная «викторина», не подсказывает действий; 2 карточки под одно и то же. Никто из конкурентов не выносит это в feed | **Объединить в одну карточку «Рекорды периода»** (best + worst внутри одной детали, Top-10 список уже есть) или убрать в деталь netCashFlow |
| `balanceRunway` | Почти-дубль `emergencyFund`: обе отвечают «на сколько месяцев хватит денег» (разница: burn с доходом vs без). Пользователь различия не считывает — две карточки с «N месяцев» рядом | **Объединить:** одна карточка «Подушка безопасности», внутри детали две строки — «если доход прекратится» и «при текущем темпе». Runway-логика (положительный netflow → сбережения) переезжает в деталь |
| `averageDailySpending` | Средняя за всё окно (для месяца — с первой транзакции) — вырожденная константа, почти не меняется. Не действенная | **Понизить:** оставить как строку в сводной детали, убрать отдельную карточку. Либо пересчитать на текущий бакет («в этом месяце в среднем X/день» — как Revolut daily allowance) |
| `totalWealth` | Дублирует сумму на главном экране | Оставить (net worth = table stakes и якорь секции Капитал), но **не** дублировать в push/digest |

Итог: −3 карточки, 2 объединения → лента короче примерно на 5 позиций без потери информации.

### Структурная проблема: «стена статистики»

Severity-сортировка работает только внутри секций — критичный `budgetOverspend` живёт в 3-й секции ниже нейтральных карточек расходов. У Copilot/Emma экран открывается с **сигналов**, а не с отчётности.

**Решение:** секция **«Важное сейчас»** вверху ленты — все insights с severity `critical`/`warning` из любых секций (максимум 3–5), затем обычные секции. Реализуется на уровне `InsightsViewModel` (уже есть `sortedBySeverity`), новых генераторов не требует.

## 3. Что добавить (gap-анализ)

Отсортировано по соотношению ценность / стоимость с учётом уже существующей инфраструктуры:

### Высокий приоритет

1. **Повышение цены подписки** — фича-визитка Emma и Rocket Money («Netflix подорожал»). У Tenra уже есть `RecurringSeries` + связанные транзакции: сигнал = фактическое списание > `series.amount` (с допуском). В KZ-банках такого нет вообще — локальный дифференциатор. Push-кандидат №1.
2. **Крупная разовая трата** — предикат Copilot: `amount > порог И не recurring` (аренда не триггерит). Порог по умолчанию относительный (например, > 3× средней транзакции или настраиваемая сумма).
3. **Итоги недели** (карточка + push по понедельникам): расходы за неделю vs прошлая, топ-категория. Самый любимый аналитический push по всем бенчмаркам (Copilot Monday, Apple Sunday). Данные уже есть в `periodPoints` week-гранулярности.
4. **Кандидаты в подписки** — повторяющиеся одинаковые списания без series («похоже на подписку — добавить?»). У всех конкурентов auto-detect есть, у Tenra series заводятся вручную — это мостик.

### Средний приоритет — уникальные для доменов Tenra (нет у конкурентов и не будет у Apple Wallet)

5. **Доход по депозитам** — «депозиты принесли X ₸ за месяц» (данные `DepositInterestService` уже считаются). Переформулировать `accountDormancy` из «спящий счёт» в **упущенную выгоду**: «на счёте N лежит X без движения 30+ дней — на депозите под ~14% это +Y/мес». В KZ-контексте очень действенно.
6. **Прогресс по кредитам** — «осталось N платежей / M месяцев до закрытия», «переплата % снизилась». Данные в `LoanInfo`.
7. **FX-инсайт** — для мультивалютных пользователей: «курс USD/KZT изменился на X% — ваши валютные счета ±Y в тенге». Инфраструктура: `CurrencyRateStore` + `currencyRatesVersion`.

### Низкий приоритет / отказаться

- **Payday detection** — доходы у пользователей Tenra в основном ручные/регулярные, ценность низкая.
- **Merchant-инсайты** — нет нормализованных мерчантов (только description), дорого.
- **Кредитный скоринг** — нет KZ-интеграции.
- **Conversational/AI-инсайты (Cleo)** — требует сервера; вне scope.

## 4. Уведомления о сигналах

### Ограничение платформы

Пуш-сервера нет; сейчас только локальные уведомления (`SubscriptionNotificationScheduler`, напоминания о списаниях в 09:00). Значит:
- сигналы детектируются **при работе приложения** (после пересчёта insights) и по **BGAppRefreshTask** (нужно добавить; iOS даёт его best-effort);
- «запланированные» уведомления (weekly digest) готовятся заранее из последних данных и обновляются при каждом фоновом/активном пересчёте.

### Архитектура (по бенчмаркам)

Модель — гибрид трёх проверенных паттернов: двухуровневость Kaspi (push vs тихая лента), бакеты Rocket Money (Alerts/Digest/Tips), per-type тумблеры Copilot.

**Push получают только сигналы-переходы, не состояния.** Ключевой компонент — `InsightSignalService`: diff свежевычисленных insights против сохранённого снапшота «последнее заалерченное состояние» (CoreData/UserDefaults: `signalId → lastFiredDate, lastValue`). Уведомление уходит только на **переходе** (не было перерасхода → появился), с дедупликацией: один и тот же `signalId` не чаще 1 раза в 7 дней, глобальный колпак ~5 push/неделю (анти-fatigue: 43% пользователей отключают уведомления из-за шума).

**Тир 1 — push (только critical/warning, всё с настраиваемыми порогами и per-type тумблерами):**

| Сигнал | Триггер (default) | Источник |
|---|---|---|
| Перерасход бюджета | категория перешла 100% | `budgetOverspend` |
| Прогноз перерасхода | projected > 110% и прошло ≥ 25% периода | `projectedOverspend` |
| Подписка подорожала | списание > series.amount + допуск | новый генератор |
| Низкий прогноз баланса | `projectedBalance` < настраиваемого порога | `projectedBalance` |
| Крупная трата | > порога и не recurring | новый генератор |
| Всплеск в категории | ≥ 2× среднего (критич. ветка spendingSpike) | `spendingSpike` |
| Итоги недели | понедельник 09:00, фикс. ритуал | periodPoints (week) |

**Тир 2 — тихая лента в приложении:** все neutral/positive сигналы + история push (bell-иконка или секция «Важное сейчас» с бейджем на табе). Ничего маркетингового в канал уведомлений — главный анти-паттерн Emma.

**Настройки:** экран «Уведомления» — 3 группы (Сигналы / Итоги / Напоминания о подписках-существующие), per-type тумблеры, слайдеры порогов (низкий баланс, крупная трата), выбор дня/времени digest. Дефолты консервативные: сигналы вкл, digest вкл, ежедневное — только opt-in.

**Тон:** нейтрально-поддерживающий, без стыжения (главная похвала Copilot); вариативные шаблоны текста, чтобы не приедалось (урок Cleo).

## 5. План действий

### Фаза A — чистка ленты (мелкая, без новых данных)
1. Удалить `incomeVsExpenseRatio` (график остаётся в детали netCashFlow).
2. Объединить `bestMonth`+`worstMonth` в одну карточку «Рекорды».
3. Объединить `balanceRunway` → в деталь `emergencyFund`.
4. `averageDailySpending` → строка в сводной детали (или пересчёт на текущий бакет).
5. Секция «Важное сейчас» вверху: топ-5 critical/warning со всех секций.

### Фаза B — новые генераторы (по чеклисту insights.md: DataSnapshot, txDateMap, piggyback на PreAggregatedData)
1. `subscriptionPriceIncrease` — series vs фактические списания.
2. `largeTransaction` — крупная не-recurring трата.
3. `weeklySummary` — карточка итогов недели.
4. `recurringCandidate` — детект повторяющихся списаний без series.
5. Рефрейм `accountDormancy` → «упущенная выгода» (связка с депозитной ставкой).
6. `depositEarnings` / `loanProgress` / `fxImpact` — доменные дифференциаторы.

### Фаза C — уведомления MVP
1. `InsightSignalService` — diff-движок «переходов» + персист последнего состояния.
2. `SignalNotificationScheduler` (по образцу `SubscriptionNotificationScheduler`) + дедуп 7d + колпак 5/нед.
3. Push для: перерасход, прогноз перерасхода, подорожание подписки, низкий прогноз баланса.
4. `NotificationSettingsView`: 3 группы, per-type тумблеры, пороги.
5. Deep-link из уведомления в соответствующий `InsightDetailView`.

### Фаза D — digest и фон
1. Weekly digest push (понедельник 09:00, содержимое из последнего пересчёта).
2. `BGAppRefreshTask`: фоновый пересчёт сигналов + обновление запланированных уведомлений.
3. Тихая лента сигналов / бейдж «Важное сейчас».

### Статус реализации (2026-07-13)

**Сделано (фазы A–D, все юнит-тесты зелёные):**
- A: `incomeVsExpenseRatio` удалён; best+worst → «Рекорды» (`period_records`); `balanceRunway` слит в `emergencyFund`; секция «Важное сейчас» (топ-5 critical/warning, дедуп из секций). `averageDailySpending` НЕ трогали — reference-док был устаревшим, метрика уже считается по текущему бакету с трендом.
- B: `subscriptionPriceIncrease` + `largeTransaction` (+тесты `InsightSignalGeneratorTests`); `accountDormancy` перефреймлен в «упущенную выгоду» (копирайт). Локализация ×11 с паритетом ключей.
- C: `InsightSignalService` (diff-переходы, дедуп 7д, колпак 5/нед; тесты `InsightSignalServiceTests`), `InsightSignalSettings` + экран настроек (master + per-type тумблеры + weekly digest + обработка denied-permission), deep-link тапа в таб «Аналитика».
- D: `WeeklyDigestScheduler` — пн 09:00, контент из последнего пересчёта `.week`, тело называет покрываемую неделю.

**Отложено (follow-ups):**
1. **BGAppRefreshTask** — сигналы/digest сейчас пересчитываются только при пересчёте инсайтов (вкладка «Аналитика»). Фоновый пересчёт требует capability Background Modes + Info.plist identifiers.
2. `recurringCandidate` (детект «похоже на подписку»), `depositEarnings`, `loanProgress`, `fxImpact` — доменные дифференциаторы из фазы B.
3. Слайдеры порогов (низкий баланс, крупная трата) — сейчас пороги зашиты в severity-гейты генераторов.
4. Обнаружено: `duplicateSubscriptions` — enum-кейс без генератора (мёртвый код, метрика из reference-дока никогда не эмитится). Решить: реализовать или удалить кейс.
5. Вариативность текстов push (пул шаблонов) — сейчас тело собирается из полей инсайта.

### Метрики успеха
- Доля пользователей с ≥1 включённым сигналом; retention push-подписчиков vs без (бенчмарк: +50% логинов у PFM с инсайтами, MX).
- Opt-out rate по типам (цель < 10%/тип); CTR push → открытие детали.

## Приложение: сводка бенчмарков

| Практика | Кто | Вывод для Tenra |

| Weekly digest в фикс. день | Copilot (пн), Apple (вс) | Самый ценимый аналитический push |
