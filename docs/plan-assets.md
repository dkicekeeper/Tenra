# План: активы и чистый капитал

> Статус: решения владельца приняты 2026-10-16 (§8), реализация не начата. Когда план реализуется, файл
> уходит в `archive/plans/`, а правила оседают в новом `domains/assets.md` (и строке в таблице
> «When to Read Which Doc» в CLAUDE.md).

---

## 1. Зачем

Tenra сегодня смотрит на деньги только как на поток: пришло, ушло, осталось на счетах. Квартира,
дом и машина в этой картине есть только как когда-то большой расход. Человек, который купил
квартиру за 24 млн ₸ в 2018 году, сегодня может продать её примерно за 70 млн ₸ и получает
500 тыс. ₸ аренды в месяц, но приложение показывает ему только то, что на счетах.

Раздел «Активы» добавляет второй взгляд: **что у меня есть и сколько это стоит**. Из него
получается **чистый капитал**: деньги + активы + что мне должны − кредиты − что я должен.

Что есть сейчас (точки опоры):
- `total_wealth` («Накопленный капитал», `InsightsService+Wealth.swift`): Σ балансов счетов без
  кредитов и с `includeInBalance`. Кредиты не вычитаются, личные долги не учитываются.
- Кредиты: счета с `LoanInfo`, остаток долга в `remainingPrincipal` ([domains/loans.md](domains/loans.md)).
- Цели и долги (v15): отдельные сущности со своим хранилищем и экранами, никогда не меняют
  балансы и операции ([domains/goals-and-debts.md](domains/goals-and-debts.md)). Это ближайший
  образец для активов.

## 2. Главное решение: не переписывать прошлое

**Покупка квартиры в 2018 году остаётся расходом.** Деньги действительно ушли со счетов, и
аналитика расходов, бюджеты и суммы на главной остаются честными (правила #8 и #11 в CLAUDE.md
не трогаем). Актив живёт рядом: у него своя цена покупки и свои оценки. В чистом капитале
квартира возвращается как 70 млн ₸.

Почему это сходится без двойного счёта:
- **Покупка в прошлом** (2018): деньги со счетов давно ушли, актив просто добавляет свою текущую
  стоимость. Капитал = сегодняшние деньги + сегодняшняя оценка.
- **Новая покупка** (машина за 10 млн с Kaspi): расход −10 млн на счёте, актив +10 млн. Капитал
  не изменился, как и должно быть: деньги превратились в вещь.
- **Ипотека**: кредитный счёт вычитается из капитала остатком долга, у актива видно, сколько в
  нём «своих» денег (оценка − остаток ипотеки).

Отвергнутая альтернатива: **актив как разновидность счёта** (`assetInfo` на `Account`, как
депозиты и кредиты). Плюс: покупку можно было бы записать переводом «в актив», и она ушла бы из
расходов, как пополнение депозита. Минус: счёт с квартирой полезет во все выборы счёта при
записи операции, в карусель на главной, в лимит «4-й счёт = Pro», в импорт выписок, в Siri, в
`BalanceCalculationEngine`. Площадь поражения как у депозитов и кредитов вместе взятых. Отдельная
сущность изолирована и повторяет свежий образец целей и долгов.

Исключить прошлые покупки из «трат» в аналитике можно позже и точечно (§9, фаза 5).

## 3. Модель

```swift
nonisolated enum AssetKind: String, Codable, CaseIterable, Sendable {
    case apartment, house, land, commercial   // недвижимость
    case vehicle                              // транспорт
    case other                                // техника, украшения, бизнес, что угодно
}

nonisolated struct AssetValuation: Codable, Equatable, Hashable, Identifiable, Sendable {
    enum Source: String, Codable, Sendable { case purchase, manual, assistant, sale }
    var id: String
    var date: Date
    var value: Double          // в валюте актива
    var source: Source
    var note: String?          // «по объявлениям на krisha.kz», «оценщик банка»
}

nonisolated struct AssetCategoryLink: Codable, Equatable, Hashable, Sendable {
    var categoryId: String     // id, не имя: категории переименовываются (renameCategoryInTransactions)
    var subcategoryId: String? // чтобы две квартиры в «Аренде» не считались дважды
}

nonisolated struct Asset: Equatable, Hashable, Identifiable {
    var id: String
    var name: String
    var kind: AssetKind
    var iconSource: IconSource?
    var currency: String
    var purchaseDate: Date?
    var purchasePrice: Double?          // nil: наследство, подарок, не помню
    var valuations: [AssetValuation]    // новые в конце; покупка = первая точка
    var depreciationPerYear: Double?    // доля в год между оценками (авто); nil = держим последнюю
    var ownershipShare: Double          // 1.0; 0.5 для дома пополам с супругом
    var linkedLoanAccountId: String?    // ипотека или автокредит
    var incomeLink: AssetCategoryLink?  // аренда
    var expenseLink: AssetCategoryLink? // содержание: налог, ОСИ, ремонт, страховка
    var includeInNetWorth: Bool
    var soldAt: Date?
    var salePrice: Double?
    var note: String?
    var order: Int
    var createdAt: Date
}
```

Хранение: `AssetEntity` в CoreData **v16** (через скилл `/coredata-schema-bump`), оценки и связи
JSON-ом на строке, как взносы у целей. `AssetRepository` (`Services/Assets/`) вне фасада
`DataRepositoryProtocol`, как `GoalRepository`. `AssetStore` (`ViewModels/`, `@Observable`)
единственный источник правды, принадлежит `AppCoordinator`, грузится после
`isFullyInitialized`, перезагружается на `CoreDataStack.storeDidResetNotification`. Бэкапы
несут его сами (файл хранилища копируется целиком), «удалить все данные» стирает.

Вся математика в одном `nonisolated enum AssetValuationMath` (`Services/Assets/`), как
`GoalProgress`: каждый экран и Тэн берут цифры только оттуда.

## 4. Как обновлять рыночную оценку

Автоматической «правды» о цене квартиры нет: у krisha.kz и kolesa.kz нет публичного API
(парсинг нарушает их правила и ломается), а приложение работает в 11 локалях и многих странах.
Поэтому оценка слоями, от надёжного к удобному:

1. **Ручная оценка (основа, фаза 1).** Кнопка «Обновить оценку» на экране актива: сумма, дата,
   откуда цифра (необязательно). Лист `MoneyEntrySheet`, как взнос в цель. Каждая оценка
   остаётся в истории, из неё строится график стоимости. Дата последней оценки видна всегда:
   «70 млн ₸ · оценка от 16 окт».
2. **Напоминание (фаза 3).** Оценке больше полугода (недвижимость и транспорт) или года
   (прочее): бейдж «устарела» на карточке и сообщение Тэна первым (`AssistantInbox`,
   ключ `asset:<id>:<полугодие>`), с кнопкой сразу в лист оценки.
3. **Правило между оценками (фаза 3, по желанию).** Для машины: «дешевеет на X% в год». Между
   ручными оценками стоимость считается от последней оценки и помечена «≈ расчёт». Новая ручная
   оценка всегда главнее и становится новой базой. Для недвижимости по умолчанию правила нет:
   держим последнюю оценку (честнее, чем придумывать рост).
4. **Помощь Тэна (фаза 4).** «Сколько сейчас стоит моя квартира?»: Тэн спрашивает район,
   площадь, год дома и цену м² из объявлений, считает и предлагает **черновик** оценки
   (`source: .assistant`). Сохраняет только человек, на карточке подтверждения.
5. **Рыночные индексы (идея, не планируем).** Официальные индексы цен на жильё по городам
   (Бюро национальной статистики) как «подсказка» к оценке. Только Казахстан, данные надо
   поддерживать: вернуться, если раздел приживётся.

## 5. Как считать

Все суммы в валюте актива; в базовую валюту через `CurrencyConverter.convertSync`, с самой
суммой как запасным вариантом при холодном кэше (правило #6).

| Показатель | Формула |
|---|---|
| Текущая стоимость | последняя оценка; с правилом износа: `оценка × (1 − d)^(лет с оценки)` |
| Доля владельца | стоимость × `ownershipShare` (в капитал идёт она) |
| Прирост | стоимость − цена покупки (нет цены покупки: не показываем) |
| Среднегодовой рост | `(стоимость / цена покупки)^(1 / лет) − 1`, только если прошло ≥ 1 года |
| Аренда за 12 мес | Σ операций `.income` по `incomeLink` за последние 12 месяцев |
| Содержание за 12 мес | Σ операций `.expense` по `expenseLink` за 12 месяцев |
| Доходность аренды | (аренда − содержание) за 12 мес / стоимость |
| Своя доля при кредите | стоимость − `remainingPrincipal` связанного кредита |
| Полный результат | прирост + Σ всей полученной аренды − Σ всего содержания с даты покупки |

Операции по связям берутся из индекса `transactionsByCategoryName` (корзина O(1), фильтр по
подкатегории и дате внутри), не проходом по 19k операций. Нужна история за много лет (полный
результат): считать в `Task.detached` на снимке (правило #9).

**Пример (квартира пользователя):** куплена в 2018 за 24 млн ₸, сейчас 70 млн ₸, аренда
500 тыс. ₸ в месяц.
- Прирост: +46 млн ₸ (+192%, в 2,9 раза).
- Среднегодовой рост за ~8 лет: около 14% в год.
- Аренда: 6 млн ₸ в год, это 8,6% от сегодняшней стоимости (и 25% в год на вложенные 24 млн).
  Чистая доходность ниже на налог на доход от аренды, ОСИ и ремонт.
- Итого квартира приносит примерно рост цены + 8,6% в год.
- Честная оговорка: заметная часть роста в тенге это инфляция и курс. Позже (фаза 5) можно
  показать то же в долларах по курсу на дату покупки и на сегодня (исторические курсы
  Нацбанка в приложении уже есть, [domains/currency.md](domains/currency.md)).

**Чистый капитал:**

```
Капитал = Деньги + Активы + Мне должны − Кредиты − Я должен

Деньги     = Σ балансов счетов (!isLoan, includeInBalance)   // как сегодня total_wealth
Активы     = Σ стоимость × доля (не проданные, includeInNetWorth)
Кредиты    = Σ remainingPrincipal активных кредитов (includeInBalance)
Мне должны / Я должен = Σ PersonalDebt.remaining открытых долгов по направлению
```

Считает `NetWorthCalculator` (`nonisolated`, на `Sendable`-снимке, как `InsightsService`). Ключ
пересчёта по правилу #12: `mutationVersion` операций, балансы, версия активов, версии целей и
долгов, кредиты (`accountsMutationVersion`), `baseCurrency`, `currencyRatesVersion` и
**сегодняшняя дата** (износ и устаревание оценок зависят от дня).

**Продажа:** «Продать» спрашивает цену и дату, добавляет оценку `source: .sale`, ставит
`soldAt`. Актив уходит из капитала (деньги теперь на счёте, если человек записал поступление) и
переезжает в раздел «Проданные» с итоговым результатом. Операцию поступления приложение само не
создаёт (как кредиты: никаких автоматических операций); можно предложить её создать одной кнопкой.

## 7. Тэн

По образцу целей и долгов ([plan-ai-assistant.md](plan-ai-assistant.md), фаза 4b):
- **Контекст:** строка `assets:` в `<app_context>` (id, имя, валюта, без сумм).
- **Чтение:** `get_assets` (стоимость, дата оценки, устарела ли, цена покупки, прирост, рост в
  год, аренда и содержание за 12 мес, доходность, своя доля) и `get_net_worth` (разбивка
  капитала). Цифры только из `AssetValuationMath` и `NetWorthCalculator`.
- **Черновики:** `draft_asset` («у меня квартира, купил в 2018 за 24 млн»), `draft_asset_valuation`
  («квартира теперь стоит 70 млн»), сохраняются на карточке подтверждения.
- **Пишет первым:** устаревшая оценка (§4.2).
- Сервер: контракт в `server/assistant/src/tools.ts`, раздел «Активы» в промпте, кейсы eval
  `ru-asset-new`, `ru-asset-valuation`, `ru-net-worth`, `en-rental-yield`.

## 8. Решения владельца (2026-10-16)

1. **Активы только в Pro.** Как долги: любой путь добавления (плюс в списке, кнопка пустого
   состояния, черновик Тэна) без Pro открывает paywall и после покупки продолжает в форму
   (`paywallSheet(onUnlocked:)`). Уже заведённые активы после окончания Pro остаются открытыми:
   смотреть, обновлять оценку, продавать, редактировать, и продолжают входить в капитал.
   Тэн без Pro на `draft_asset` отвечает отказом с подсказкой про Pro (как `draft_debt`).
   Инсайт «Чистый капитал» бесплатный, как вся аналитика: без активов он считает деньги,
   долги и кредиты. При реализации добавить активы в список Pro в CLAUDE.md (Monetization) и
   в [promotion-plan.md](promotion-plan.md) §2.
2. **Карточка «Активы» в «Финансах» сразу после «Депозитов».** Новая карточка, порядок и вид
   существующих не меняются.
3. **Два капитала не нужны.** Нынешний «Накопленный капитал» (`total_wealth`, ключ
   `insights.wealth.title`) переименовывается в «Деньги на счетах» во всех 11 локалях, формула
   у него прежняя. Рядом новый «Чистый капитал» (`net_worth`) с полной формулой §5. Название
   раздела «Капитал» остаётся. Вынести капитал героем наверх «Финансов» можно позже, отдельным
   решением.
4. **Кредиты вычитаются из капитала всегда**, даже без активов.
5. **Износ для машин по умолчанию выключен**, процент человек ставит сам (подсказка в поле,
   без утверждений о рынке).

## 9. Фазы

Каждая фаза отдельный PR, со сборкой, тестами и 11 локалями (без длинных тире в строках UI).

**Фаза 1. Активы (MVP).** Модель, v16, `AssetRepository`, `AssetStore`, `AssetValuationMath`
(стоимость, прирост, рост в год, своя доля при кредите); карточка в «Финансах», список, детали
с графиком оценок, редактирование, ручная оценка, продажа; гейт Pro на добавление (§8.1). Тесты:
математика, round-trip репозитория на in-memory CoreData (`.sharedProcessState`), миграция
v15 → v16.

**Фаза 2. Доход и капитал.** Связи с категориями аренды и содержания (id, с выбором
подкатегории; две связи на одну категорию без подкатегории запрещены), доходность, полный
результат; если операций аренды нет, предложить завести регулярный доход (`RecurringStore`).
`NetWorthCalculator`, инсайт `net_worth` и переименование `total_wealth` в «Деньги на счетах»
(§8.3, 11 локалей). Тесты: мультивалютность, проданные и доля вне капитала, ипотека, кредиты
без активов (§8.4).

**Фаза 3. Актуальность.** Бейдж «оценка устарела», напоминание через `AssistantInbox`, правило
износа, график чистого капитала во времени (деньги: существующая линия
`cumulativeBalancePoints`; активы: ступеньки по оценкам; кредиты: остаток из
`generateAmortizationSchedule` на конец периода).

**Фаза 4. Тэн.** §7 целиком: инструменты, черновики, промпт, eval.

**Фаза 5. Идеи, не планируем пока.**
- Привязать операции покупки и ремонта к активу («это вложение в актив»): цена покупки из
  операций, а аналитика показывает траты «без покупок активов». Только в отдельных метриках
  (средние траты, аномалии), суммы на главной остаются на `summaryContribution` (правило #11).
- Доходность в долларах и с поправкой на инфляцию.
- Экспорт активов в CSV (данные пользователя всегда выгружаются).
- Индексы цен на жильё как подсказка (§4.5).

## 10. Риски

- **Устаревшая оценка выглядит как факт.** Дата оценки рядом с суммой всегда, расчётная
  стоимость помечена «≈».
- **Двойной счёт аренды** двумя активами на одной категории: запрет в редакторе (§9, фаза 2).
- **Удалённые категория или кредит**: связь читается как пустая, актив не ломается.
- **Кэши капитала**: полный ключ по правилу #12, иначе капитал не обновится после смены курса
  или новой операции до перезапуска.
- **Превью**: новый `@Environment(AssetStore.self)` требует обновить каждый `#Preview` в файле
  (gotchas.md).
