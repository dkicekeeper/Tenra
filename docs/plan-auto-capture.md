# План: автоматическая запись оплат и мерчанты

> Статус: решения владельца приняты 2026-10-19 (§3), фаза 1 в работе (§9). Когда план
> реализуется, файл уходит в `archive/plans/`, а правила оседают в
> [domains/intents.md](domains/intents.md) §6 и [domains/logos.md](domains/logos.md).

---

## 1. Зачем

Wallet-автоматизация уже записывает оплаты Apple Pay через `AddExpenseIntent` (сумма, заметка ←
мерчант, счёт задан в автоматизации), а `MerchantCategoryMemory` помнит категорию мерчанта. Но:

- оплата в другой валюте пишется в валюте счёта (`AddExpenseIntent` берёт `account.currency`):
  12,50 € с карты в тенге становятся 12,50 ₸;
- новый мерчант останавливает автоматизацию вопросом о категории, хотя `brandPresetId` и история
  часто знают ответ;
- двойное срабатывание терминала даёт две операции;
- на каждую карту нужна своя автоматизация с заданным счётом;
- мерчант живёт только строкой в `description`: ни логотипа, ни чистого имени, ни своего экрана.

Цель: оплата записывается молча и правильно, всё угаданное собирается в «На проверку», а мерчант
становится сущностью с логотипом, на которой строятся новые экраны и инсайты.

## 2. Ограничения платформы

- **Wallet-триггер ловит только прикладывание к терминалу** (iPhone и Apple Watch). Онлайн-оплаты
  Apple Pay на сайтах и в приложениях он не вызывает: Apple это не документирует, другие трекеры с
  той же автоматизацией пишут прямо, что работают только физические оплаты. Из приложения не
  исправить.
- **Что передаёт Wallet:** Amount (сумма с вложенным Currency Code), Merchant, Card or Pass, Date.
  Категории мерчанта (MCC) нет. Currency Code выбирается только через промежуточную переменную
  (Set Variable ← Amount, затем её Currency Code), поэтому у действия сумма числом и код валюты
  отдельными параметрами, как у других трекеров.
- **Триггер ненадёжен:** иногда отваливается по таймауту, иногда приходит пустой мерчант и сумма 0,
  по сообщениям разработчиков срабатывает и на отклонённую оплату. Отсюда сверка с выпиской (§6).
- **Пуши банков недоступны** чужим приложениям, SMS и email владелец исключил (все банки шлют пуши),
  FinanceKit работает только в США и Великобритании, Kaspi не даёт доступа к операциям. Остальные
  операции (переводы, Kaspi QR, онлайн-оплаты) попадают в Tenra через выписку, чек по «Поделиться»
  или вручную.

## 3. Решения владельца (2026-10-19)

1. **Логотипы ищутся и в logo.dev по имени мерчанта** (`img.logo.dev/name/{name}?fallback=404`),
   после локального справочника и tenra-assets.
2. **Логотип вместо иконки категории** в строке операции: переключатель в Настройках, по
   умолчанию включён.
3. **Новый мерчант сохраняется сразу**, без вопросов в момент оплаты. Угаданное (категория, счёт)
   попадает в «На проверку» и в уведомление.
4. **Wallet-действию разрешён один сетевой запрос курса.** Если курса нет и сети нет, оплата ждёт в
   очереди и записывается, когда курс появится (при следующей оплате или открытии приложения).
5. **Всё бесплатно**, Pro не трогаем.
6. **SMS и email не используем.**

## 4. Фаза 1. Тихое Wallet-действие

Новое действие `LogWalletPaymentIntent` («Записать оплату Apple Pay»). `AddExpenseIntent` не
меняется, чтобы не сломать уже настроенные автоматизации.

**Параметры:** сумма (число), код валюты, мерчант, карта, счёт (необязательный).

**Порядок обработки** (`WalletPaymentRecorder`):
1. Сумма ≤ 0 (турникет, сбой триггера) → пропуск без записи.
2. Повтор: та же сумма, валюта, мерчант и карта за 90 секунд → пропуск.
3. Счёт: заданный в автоматизации → запомненный для карты (`CardAccountMemory`) → единственный
   подходящий счёт → подсказка по истории категории (`IntentAccountSuggester`) → первый подходящий.
   Последние два варианта считаются догадкой.
4. Категория: память мерчанта (`MerchantCategoryMemory`, с подкатегориями) → история того же
   мерчанта (узкая выборка из CoreData, без полной загрузки) → бренды → ключевые слова голосового
   парсера → «Другое». Всё, кроме памяти, считается догадкой.
5. Валюта: код от Wallet; если отличается от валюты счёта, курс из кэша, иначе сетевой запрос,
   иначе очередь (`WalletCaptureStore.pending`).
6. Запись через `TransactionDraftService.commit`. Догадка о счёте не учит `VoiceLearningStore`.
7. Запись в журнал (`WalletCaptureStore`): мерчант, карта, что угадано. Журнал хранит 90 дней.

**Обучение:** правка такой операции в приложении (категория, подкатегории, счёт) запоминает мерчанта
и карту, даже если раньше их не было в памяти, и снимает операцию с проверки.

**Фаза 1б (UI):** список «На проверку» (`WalletReviewView`): нажатие открывает правку, свайп
вправо и «Всё верно» запоминают текущую категорию и счёт. Уведомление «Проверьте оплату» после
записи с догадкой, одно на мерчанта, без суммы; нажатие открывает список. Вход из Настройки → Siri и
Быстрые команды, там же список карт (`WalletCardsView`). DEBUG-проба удалена. Инструкция по
настройке в приложении ждёт проверки на устройстве: точные русские названия полей Wallet в
Быстрых командах.

**Фаза 1в:** оплата подписки (APPLE.COM/BILL и т.п.) привязывается к платежу активной серии, а не
создаёт вторую операцию; логика сопоставления из `ImportDuplicateDetector.subscriptionOccurrence`.

## 5. Фаза 2. Справочник мерчантов и логотипы

- `MerchantCategoryMemory` становится справочником мерчантов (тот же ключ UserDefaults): категория
  и подкатегории, чистое имя, домен бренда, состояние логотипа (найден, нет, выбран вручную, дата
  последней попытки). Поле `merchant` в `Transaction` не добавляем: всё ищет по `description`.
- **Чистое имя:** «MAGNUM CASH&CARRY 123» → «Magnum Cash&Carry». Убрать номера точек, префиксы
  процессинга (SQ \*, PAYPAL \*), ТОО/ИП/LLP/LLC, город и страну в конце. Пользователь может
  переименовать.
- **Поиск логотипа** (только в приложении, только для мерчантов из справочника или встреченных ≥ 2
  раз): `ServiceLogoRegistry` и алиасы мерчантов → индекс tenra-assets (сопоставление локальное) →
  logo.dev по имени с `fallback=404` → ничего (остаётся иконка категории). Без буквенной заглушки и
  Google favicon. «Нет логотипа» перепроверяется раз в 30 дней. `brandPresets` связать с доменами,
  в tenra-assets добавить топ мерчантов Казахстана.
- **Отображение:** в `TransactionCard` логотип мерчанта третьим после подписки и кредита,
  переключатель в Настройках (по умолчанию вкл.). Ключ обновления строки включает версию
  справочника (красный флаг #12).
- Ручной выбор логотипа в `MerchantCategoryEditView` (существующий пикер брендов + «Без логотипа»).

## 6. Фаза 3. Операции без Apple Pay

- **Чек из банковского приложения через «Поделиться»:** PDF уже открывается в Tenra (ассистент), нужно
  добавить картинки (`public.image` в `CFBundleDocumentTypes`) и распознавание чека перевода и Kaspi
  QR: получатель, сумма, дата, комиссия. Получатель становится «мерчантом» с памятью категории; если
  он есть в личных долгах, предложить «это возврат долга?».
- **Сверка с выпиской:** при импорте операции из Wallet, которых нет в выписке, показать как
  «не найдены, возможно отклонены, удалить?». Импорт уже не дублирует их
  (`ImportDuplicateDetector`, ±1 день).
- **Напоминание об импорте:** если по счёту давно нет выписки, мягкое уведомление.

## 7. Фаза 4. Фичи на данных мерчантов

1. Экран мерчанта на `EntityDetailScaffold`: логотип с подсветкой (`DominantColorExtractor`), сумма
   за месяц и год, визиты, средний чек, график по месяцам, операции.
2. Инсайты: топ мерчантов, рост среднего чека. Через `summaryContribution` и `convertSync`
   (красные флаги #6, #11), в фоне.
3. Поиск подписок: один мерчант, похожая сумма, интервал около месяца, ≥ 3 раз → «создать подписку?».
4. Ten: группировка по нормализованному мерчанту в `FinanceToolkitCompute`.
5. Мерчанты с логотипами в подсказках поиска Истории (`.dsSearchSuggestions`).
6. Импорт выписки берёт категорию и логотип из справочника.

## 8. Проверка на устройстве

Не покрывается юнит-тестами: настройка автоматизации с новым действием, тихий запуск при
заблокированном экране, оплата в другой валюте (код приходит?), карта (строка «Card or Pass»
стабильна?), повтор терминала, запись из холодного процесса и из запущенного приложения
(Home обновляется по `mutationVersion`).

**Настройка автоматизации** (названия полей Wallet по-английски, русские подписи в Быстрых
командах сверить на устройстве): Автоматизация → Wallet → любые карты, «Выполнять сразу»,
категорию Transport снять. Действия: Set Variable `Payment` ← Shortcut Input → Amount; «Записать
оплату Apple Pay»: сумма ← `Payment` → Currency Amount (вторая строка с этим именем, ниже Currency
Code), код валюты ← `Payment` → Currency Code, мерчант ← Shortcut Input → Merchant, карта ←
Shortcut Input → Card or Pass. «Показывать при запуске» выключить.
