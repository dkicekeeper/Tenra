- **007 backspace + TransactionCard**: вместо Button-обёртки для backspace
  использован `onPressingChanged` существующего long-press (fallback самого
  плана) — сохраняет tap+long-press без риска. Клавиши цифр/операторов →
  `.buttonStyle(.bounce)`. TransactionCard/tapAction-строки обёрнуты в Button+.bounce.
- **009 ExpenseIncomeProgressBar**: `withAnimation` требует non-optional
  `Animation`, поэтому там `barAnimation` — инстанс-свойство с env-гейтом
  (`.linear(0)` под RM), а не общий optional-токен `progressFillAnimation`
  (последний применён к `.animation(value:)`-сайтам, которые принимают optional).
- **010/012 InsightDetailView(PagedCategoryBreakdownView)**: тип generic →
  `pageAnimation` сделан computed instance property (static stored в generic
  запрещён).

### Animation findings deferred (no plan written; recorded so future audits don't re-litigate)

- **Per-digit spring на вводе суммы** (`AnimatedInputComponents.swift:115-117`) —
  по букве плейбука анимация на typing, но `.numericText()` — нативный идиом,
  kern-инженерия сделана именно ради него, и design-system §9 явно санкционирует
  `contentSpring` для amount inputs. Осознанное решение; опционально можно
  ужать пружину до ~0.2 response для быстрого набора.
- **Facepile pop от scale 0.5 реплеится при каждом визите Finances**
  (`PackedCircleIconsView.swift:159,173` — `@State hasAppeared`) — MEDIUM-кандидат
  на «играть один раз за сессию / смягчить до 0.8»; отложено как вкусовое решение владельца.
- **Sheet-хореография через `asyncAfter(0.3)`** (`DepositsListView.swift:160`,
  `AccountsManagementView.swift:240,280,300`) — не-прерываемая догадка о времени
  системного dismiss; правильный фикс — презентация из `onDismiss:`. Редкие флоу; отложено.
- **BounceButtonStyle симметричный press/release** (`AppAnimation.swift:126-131`) — LOW-полировка
  (press-in должен быть быстрее release-out).
- **FinanceCard empty↔content чистый crossfade** (`FinanceCard.swift:49-60`) — LOW,
  добавить `.scale(0.97)` к opacity.
- **`.linear(duration: 0)` в `fastAnimation` гасит opacity-fades при Reduce Motion** — частично
  решается планом 009 (chartBannerFade); остальные сайты `fastAnimation` — по мере встречи.
- **Onboarding keyframe-пульсации без Reduce Motion гейта** (`LoopOnBoardingView.swift:69-118`) —
  редкий экран, delight-бюджет; гейтить или нет — решение владельца.

## Findings considered and rejected

Recorded so future audits don't re-litigate them:

- **logo.dev key in `Info.plist`** — `pk_`-prefixed publishable key, designed to
  be embedded client-side. By design, not a leak.
- **`NSUbiquitousContainerIsDocumentScopePublic = true`** — required for the
  tap-to-restore-in-Files backup feature; "public" = visible to the *user* in
  iCloud Drive, not to other people. By design.
- **Supabase JWT in git history** (historic `Info.plist` revisions up to commit
  `aa37302`) — real artifact, but anon-tier key for a backend abandoned when
  logos moved to jsDelivr. **RESOLVED 2026-06-12**: verified the project host
  (`mnkgheldjygknjghcpgy.supabase.co`) returns NXDOMAIN — project is deleted,
  the leaked key is inert. No rotation possible or needed; history rewrite
  not warranted.
- **"Views over-subscribe via `transactions.count`"** — misread by the auditor;
  the touch is the *documented required* observation pattern because
  `mutationVersion` is `@ObservationIgnored` (CLAUDE.md, "Entity detail view
  refresh trigger").
- **"Deposit/Loan edit screens missing"** — false; `DepositEditView.swift` and
  `LoanEditView.swift` exist.
- **TransactionStore god-object split** — real (highest-churn, ~80 call sites)
  but L effort / HIGH regression risk mid-release-cycle. Revisit after 1.1
  ships; a fresh TransactionStore *test suite* (see plan 004 maintenance notes)
  should precede any split.
- **`FileManager.urls(for:)[0]` force-indexing (5 sites)** — real pattern,
  ~zero practical crash risk on iOS (Documents always resolves). Not worth a plan.
- **CoreData `mergeChanges` error handling, InsightsViewModel generation race,
  voice-parser index access** — auditors confirmed all are safe as written;
  defensive-hardening only.
- **Full balance recalc on MainActor (`processRecalculateAll`)** — real and
  acknowledged in code comments; deferred, not rejected. Needs the
  Sendable-snapshot treatment (CLAUDE.md Red Flag #9). Candidate for the next
  planning round; targeted recalc (`recalculateBalances(for:)`) already covers
  the common paths.
- **Detail-view refresh-pattern duplication (Loan/Deposit), SwiftLint absence,
  Makefile absence, deprecated no-op `updateRecurringTransaction`** — all real,
  all low-leverage; batch into a hygiene pass if/when one happens.
