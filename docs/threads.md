# Тэн в Threads

Аккаунт Тэна в Threads: короткие посты про деньги от лица помощника Tenra, по одному в день,
без участия основателя, кроме согласия на посты раз в неделю. Решение основателя 25.11.2026:
исключение из «без SMM» ([promotion-plan.md](promotion-plan.md) §3), потому что соцсеть ведёт
Тэн, а не основатель.

## Как устроено

| Файл | Что делает |
|---|---|
| `social/threads.json` | Профиль (имя, описание, аватар) и посты по порядку: `id`, `text`, `approved`, необязательные `notBefore` (дата по Алматы) и `image` (путь в репозитории) |
| `social/threads-posted.json` | Что уже вышло: `id` → `media` (id поста в Threads) и время. Пишет workflow |
| `social/ten-avatar.png` | Аватар аккаунта, 1080×1080 |
| `scripts/threads.py` | `check` (файл постов), `me` (чей токен), `post-next [--dry-run]`, `refresh`, `stats [--days 30]` |
| `scripts/test_threads.py` | Тесты без сети: `python3 -I scripts/test_threads.py` |
| `.github/workflows/threads.yml` | Каждый день в 18:17 по Алматы плюс случайные 0-50 минут публикует следующий одобренный пост и коммитит `threads-posted.json`; по понедельникам обновляет токен. Вручную: Actions → Threads, команда и `args` |

- **Публикуется** первый по порядку пост с `"approved": true`, которого нет в
  `threads-posted.json` и чья дата `notBefore` наступила. Один пост за запуск, один запуск в день.
  Нет одобренных: запуск ничего не делает.
- **Картинка** (`image`): Threads скачивает её сам по публичной ссылке
  `raw.githubusercontent.com/.../main/<путь>`, поэтому файл должен быть в `main` до публикации.
- **Токен** `THREADS_ACCESS_TOKEN`: долгий токен пользователя Threads, живёт 60 дней. `refresh`
  продлевает его по понедельникам (Meta продлевает токен не моложе суток) и, если Meta вернула
  новую строку, записывает её в секрет репозитория через `GH_SECRETS_TOKEN`. Токены не печатаются.
  Пока секрета нет, запуски по расписанию проходят с пометкой и ничего не делают.
- **Лимиты Meta:** 250 постов в сутки, 500 знаков в посте; `check` проверяет длину, повтор `id`,
  дату, длинные тире и эмодзи до публикации.

## Голос Тэна

- По-русски, на «вы», дружелюбно и просто. Тэн: «несколько сотен частиц в капле», живёт в Tenra.
- **Без морали:** не стыдит за траты, не учит «экономить на кофе». Факт, наблюдение, маленькое
  действие на сегодня.
- **Без эмодзи и без длинных тире** (правило основателя для всех текстов для людей), до 500 знаков,
  лучше 250-350.
- Цифры в тенге, с пробелом в тысячах (`35 880 ₸`), проверены (проценты, ставки, суммы за год).
- Пост чаще всего кончается вопросом: ответы поднимают охват. Ссылка на приложение не в каждом
  посте: она в профиле.
- Нельзя: советы по инвестициям и конкретным банкам, обещания дохода, чужие данные, реальные
  выписки и суммы пользователей ([CLAUDE.md](../CLAUDE.md), выписки), политика, религия.
- Ритм недели (не жёсткий): знакомство или вопрос аудитории, упражнение, подписки, привычка учёта,
  вклад или кредит простыми словами, правило покупок, вопрос.

## Согласие основателя

1. Субботняя сессия ([promotion-plan.md](promotion-plan.md) §7) дописывает в конец
   `social/threads.json` семь постов следующей недели с `"approved": false` и `id` вида
   `w<неделя>-<номер>-<тема>` и показывает их основателю в итоге сессии.
2. Основатель отвечает «да» (или правит текст): `approved` становится `true`, коммит в `main`.
   Без его слова ни один пост не выходит.
3. Workflow публикует по одному в день. Снять пост: `approved: false` до публикации; удалить
   вышедший пост можно только в приложении Threads.

## Разовая настройка (основатель)

1. **Аккаунт Threads** для Тэна (нужен аккаунт Instagram): имя «Тэн из Tenra», аватар
   `social/ten-avatar.png`, описание из `social/threads.json` → `profile.bio`, ссылка в профиле:
   ссылка кампании App Store (шаг 6). Профиль публичный.
2. **Приложение Meta:** developers.facebook.com → Create App → сценарий «Access the Threads API».
   Разрешения: `threads_basic`, `threads_content_publish`, `threads_manage_insights`,
   `threads_read_replies`.
3. **Тестер:** в приложении Meta → App roles → Roles → Add People → Threads Tester, аккаунт Тэна.
   Принять приглашение в Threads: Настройки → Учётная запись → Разрешения для сайтов →
   Приглашения. Публиковать от своего аккаунта приложению хватает этой роли, проверка Meta (App
   Review) не нужна.
4. **Токен:** в приложении Meta → Use cases → Threads API → Settings → User Token Generator →
   Generate Access Token для аккаунта Тэна. Это короткий токен на час; обменять его на долгий
   (60 дней) в Graph API Explorer или запросом `th_exchange_token` из документации Meta.
5. **Секреты GitHub** (Settings → Secrets and variables → Actions):
   - `THREADS_ACCESS_TOKEN`: долгий токен из шага 4;
   - `GH_SECRETS_TOKEN`: fine-grained personal access token только на этот репозиторий, право
     «Secrets: Read and write» (чтобы `refresh` сохранял продлённый токен), срок год.
   Токены не вставлять в чат и в файлы: только в секреты.
6. **Ссылка кампании:** App Store Connect → Аналитика → Источники → Кампании → создать ссылку с
   кампанией `threads` (вид `https://apps.apple.com/app/apple-store/id6761530361?pt=<код
   провайдера>&ct=threads&mt=8`) и поставить её в профиль Threads. Тогда установки из Threads
   видны в App Analytics отдельно.
7. **Проверка:** Actions → Threads → `me` (имя и id аккаунта), потом `post-next` с
   `args: --dry-run` (какой пост вышел бы).

## Как мерить

- `stats` (Actions → Threads, `args: --days 7`): по каждому посту просмотры, лайки, ответы,
  репосты, цитаты, пересылки; по аккаунту просмотры, клики по ссылкам и подписчики. Субботняя
  сессия запускает его и пишет итог недели в [promotion-plan.md](promotion-plan.md) §6.
- Установки: App Analytics → Источники → Кампании → `threads` (с шага 6), и «Веб-переходы» с
  `threads.net`/`threads.com`.
- Через 4 недели решение: продолжать, менять темы или закрыть. Ориентир: подписчики растут
  каждую неделю, ссылку в профиле нажимают, из кампании `threads` есть установки.
