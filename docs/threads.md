# Tenra в Threads

Аккаунт приложения Tenra в Threads, [@tenra.app](https://www.threads.com/@tenra.app) (решение основателя 25.11.2026; не от лица Тэна и не от
основателя). Главное в нём **ответы людям, которые сами просят посоветовать приложение для учёта
расходов**: такие вопросы появляются несколько раз в неделю, под каждым 3-6 разработчиков со
ссылками (Qalta, Summa, Topf, «Трата», Obolos, cabe), и читает их ровно тот, кто сейчас выбирает
приложение. Посты нужны, чтобы профиль не был пустым: пять базовых (по одному отличию Tenra) и потом 1-2 в неделю.
Основатель только говорит «да» на черновики; соцсеть от своего лица он не ведёт
([promotion-plan.md](promotion-plan.md) §3).

## Как устроено

| Файл | Что делает |
|---|---|
| `social/threads.json` | Профиль (имя, описание, аватар), `posts` по порядку (`id`, `text`, `approved`, необязательные `notBefore`, дата по Алматы, и `image`, путь в репозитории) и `replies`: ответы на чужие посты (`id`, `replyTo` ссылка на пост, `replyToId` его id в Threads, `text`, `approved`) |
| `social/threads-posted.json` | Что уже вышло: `id` → `media` (id в Threads) и время. Пишет workflow |
| `social/tenra-avatar.png` | Аватар аккаунта: иконка приложения, 1080×1080 |
| `scripts/threads.py` | `check` (файл), `me` (чей токен), `post-next [--dry-run]`, `replies [--dry-run]`, `refresh`, `stats [--days 30]` |
| `scripts/test_threads.py` | Тесты без сети: `python3 -I scripts/test_threads.py` |
| `.github/workflows/threads.yml` | Пуш в main, который меняет `social/threads.json` (согласие основателя): сразу публикует одобренные ответы. Каждый день в 18:17 по Алматы плюс случайные 0-50 минут: следующий одобренный пост и ответы, что ещё ждут. По понедельникам обновляет токен. Вручную: Actions → Threads, команда и `args` |

- **Пост:** первый по порядку с `"approved": true`, которого нет в `threads-posted.json` и чья дата
  `notBefore` наступила. Один в день.
- **Ответ:** `reply_to_id` = `replyToId` (API Meta, разрешение `threads_content_publish`). Не больше
  трёх за запуск (`REPLIES_PER_RUN`): пачка ответов со ссылками похожа на спам. `replyToId` берётся
  из поиска по Threads (поле `pk` поста у ScrapeCreators); что это тот же id, что ждёт API Meta,
  проверяется на первом ответе: если API ответит ошибкой id, ответ опубликовать руками и
  поправить способ.
- **Картинка** (`image`): Threads скачивает её сам по публичной ссылке
  `raw.githubusercontent.com/.../main/<путь>`, поэтому файл должен быть в `main` до публикации.
- **Видео** (`video`): `.mp4` в `docs/public/media/threads/`, до 20 МБ; Threads скачивает его с сайта
  (`https://dkicekeeper.github.io/Tenra/media/threads/<файл>`, GitHub Pages отдаёт `video/mp4`),
  поэтому файл должен быть в `main` и выложен на сайт до публикации. Скрипт ждёт, пока Meta
  обработает видео (до 6 минут), и только потом публикует. У поста либо картинка, либо видео.
  Что и как снимаем: [plan-threads-videos.md](plan-threads-videos.md).
- **Токен** `THREADS_ACCESS_TOKEN`: долгий токен пользователя Threads, живёт 60 дней. `refresh`
  продлевает его по понедельникам (Meta продлевает токен не моложе суток) и, если Meta вернула
  новую строку, записывает её в секрет репозитория через `GH_SECRETS_TOKEN`. Токены не печатаются.
  Пока секрета нет, запуски по расписанию и по пушу ничего не делают.
- **Лимиты Meta:** 250 публикаций в сутки, 1000 ответов в сутки, 500 знаков; `check` проверяет
  длину, повтор `id`, дату, `replyToId` у ответа, длинные тире и эмодзи до публикации.
- **Поиск вопросов:** API Meta ищет по словам только в своих постах, пока приложение не прошло
  проверку Meta на `threads_keyword_search`. Поэтому вопросы ищет сессия Claude через Firecrawl
  (ScrapeCreators `threads/search-posts` и `threads/post`, около 2 кредитов за запрос; веб-поиск
  `site:threads.com посоветуйте приложение учет расходов`).

## Голос Tenra

- По-русски, на «вы», взросло и просто: «мы делаем Tenra». Без маскота, без шуток ради шуток.
- **Слова Казахстана:** «депозит», не «вклад» (решение основателя 26.11), как и в приложении.
- **Честно, кто пишет:** в ответе всегда видно, что это команда приложения («мы её делаем»).
- **Упор на то, чего нет у конкурентов** (решение основателя 26.11; список отличий:
  [promotion-plan.md](promotion-plan.md) §1 «Конкуренты», на 26.11 с Qalta и Traty): депозиты с
  капитализацией и начислением по дням, квартира и машина с оценкой по объявлениям и капитал в
  Аналитике, помощник Тэн (спросить словами, черновики записей, план), кредит с графиком, где видно,
  сколько уйдёт на проценты, и досрочным погашением (меньше платёж или срок), голосовой ввод, запись
  из уведомлений банков (iOS 27). Долги, подписки, Apple Pay, выписки и валюты есть и у других:
  только если человек сам об этом спросил.
- **Правда о приложении:** только то, что есть в вышедшей версии, каждая возможность сверена с
  доменным документом (`docs/domains/*.md`); в ответе, что в Tenra Pro, так и сказать (учёт
  бесплатный до трёх счетов; выписки, депозиты, кредиты, голос, долги, имущество в Pro;
  [CLAUDE.md](../CLAUDE.md) «Gated»).
- **Никаких цен и сумм** (решение основателя 26.11): ни цен Tenra Pro, ни сумм в тенге или
  другой валюте в примерах. Проценты ставок тоже не нужны: рассказываем, что умеет приложение.
- **Без эмодзи и без длинных тире** (правило основателя для текстов для людей), до 500 знаков;
  ответ 2-4 строки.
- Нельзя: советы по инвестициям и конкретным банкам, обещания дохода, чужие данные, реальные
  выписки, политика, религия; сравнение с конкурентами по имени.

## Где отвечать и где нет

- **Да:** пост, где человек просит посоветовать приложение или программу для учёта расходов,
  бюджета, подписок, депозитов (человек может написать и «вкладов»), свежий (до 3 дней), с открытыми ответами.
- **Ответ под запрос человека:** перечислить то из его списка, что Tenra умеет, и добавить одно
  отличие из «Голоса Tenra», которое ему подходит (просит депозиты: капитализация по дням; кредит:
  график и досрочное погашение); честно, если чего-то нет (общего бюджета на двоих, Android).
  Если Tenra не подходит (нужен Android, совместный бюджет), не отвечать.
- **Нет:** посты Даниеля Токкожина (Qalta) и других разработчиков и их ответы; посты, где
  человек ничего не спрашивает (жалобы, «покажите расходы»); старые ветки; второй ответ в ту же
  ветку или тому же человеку; массовые одинаковые ответы.
- **Ссылка в ответах и в профиле:** ссылка кампании `threads`,
  `https://apps.apple.com/app/apple-store/id6761530361?pt=128728453&ct=threads&mt=8`
  (установки по ней видны в App Store Connect → Аналитика → Кампании, от 5 человек).

## Согласие основателя

1. Ежедневная задача «Tenra: ответы в Threads» (облако, включается после разовой настройки)
   ищет вопросы за последние сутки и дописывает в `replies` черновики с `"approved": false`, а в
   итоге сессии показывает основателю вопрос, ссылку и текст ответа.
2. Основатель отвечает в той же сессии «да» (или правит): сессия ставит `approved: true` и пушит
   в main, workflow публикует ответ в течение пары минут.
3. Посты: субботняя сессия ([promotion-plan.md](promotion-plan.md) §7) пишет 1-2 поста на неделю
   черновиками и показывает их в итоге.
4. Без «да» основателя ничего не выходит. Снять: `approved: false` до публикации; удалить
   вышедшее можно только в приложении Threads.

## Разовая настройка (основатель)

1. **Аккаунт Threads** приложения (нужен аккаунт Instagram на отдельном ящике приложения, не на
   личном адресе: с одним адресом на двух аккаунтах Meta открывает при входе личный; адреса с
   `+` и точкой в Gmail Meta считает тем же ящиком): имя
   «Tenra», аватар `social/tenra-avatar.png`, описание из `social/threads.json` → `profile.bio`,
   ссылка в профиле: ссылка кампании App Store (шаг 6). Профиль публичный.
2. **Приложение Meta** (под личным Facebook основателя, не через work.meta.com): developers.facebook.com → Create App, название без слов Threads, Meta и Instagram (у нас «Tenra Posts»), сценарий «Access the Threads API», без бизнес-портфолио.
   Разрешения: `threads_basic`, `threads_content_publish`, `threads_manage_insights`,
   `threads_read_replies`, `threads_manage_replies`.
3. **Тестер** (если генератор токена отвечает «The user has not accepted the invite», приглашение не принято): в приложении Meta → App roles → Roles → Add People → Threads Tester, аккаунт Tenra.
   Принять приглашение в Threads: Настройки → Учётная запись → Разрешения для сайтов →
   Приглашения. Публиковать от своего аккаунта приложению хватает этой роли, проверка Meta (App
   Review) не нужна.
4. **Токен:** в приложении Meta → Use cases → Threads API → Settings → User Token Generator →
   Generate Access Token напротив аккаунта Tenra (войти аккаунтом Tenra). Генератор сразу выдаёт
   долгий токен на 60 дней; обменивать не нужно.
5. **Секреты GitHub** (Settings → Secrets and variables → Actions):
   - `THREADS_ACCESS_TOKEN`: долгий токен из шага 4;
   - `GH_SECRETS_TOKEN`: fine-grained personal access token только на этот репозиторий, право
     «Secrets: Read and write» (чтобы `refresh` сохранял продлённый токен), срок год.
   Токены не вставлять в чат и в файлы: только в секреты.
6. **Ссылка кампании** (создана 26.11): App Store Connect → Аналитика → Приобретение → Кампании →
   «Создать ссылку на кампанию», кампания `threads`: `https://apps.apple.com/app/apple-store/id6761530361?pt=128728453&ct=threads&mt=8`.
   Поставить в профиль Threads (Редактировать профиль → Ссылки); ответы берут её отсюда.
7. **Проверка:** Actions → Threads → `me` (имя и id аккаунта), потом `post-next` с
   `args: --dry-run`.
8. **Ежедневная задача:** claude.ai → запланированные задачи → «Tenra: ответы в Threads»
   (создана выключенной): добавить ей коннекторы Firecrawl и GitHub (без них сессия не найдёт
   вопросов и не проверит публикацию; задача, созданная из облачной сессии, коннекторов не
   получает) и включить. Или сказать Claude «аккаунт Threads готов», он включит, а коннекторы
   всё равно добавить в интерфейсе. Три базовых поста ждут вашего «да».

## Как мерить

- `stats` (Actions → Threads, `args: --days 7`): по каждой публикации просмотры, лайки, ответы,
  репосты, цитаты, пересылки; по аккаунту просмотры, клики по ссылкам и подписчики. Субботняя
  сессия пишет итог недели в [promotion-plan.md](promotion-plan.md) §6.
- Установки: App Analytics → Источники → Кампании → `threads` (с шага 6), и «Веб-переходы» с
  `threads.net`/`threads.com`.
- Через 4 недели после первого ответа решение: продолжать, менять или закрыть. Ориентир: из
  кампании `threads` есть установки, на ответы отвечают, аккаунт не ограничен Meta.
